# ADR 0001：可复现 VOC 检测契约

[English](0001-reproducible-voc-detection-contracts.md)

- 状态：已接受
- 日期：2026-08-17
- 读者：修改数据、模型、训练、评估或产物兼容性的维护者与贡献者

## 背景

目标检测连接多个有状态系统：源图像与 XML、划分策略、坐标转换、可变尺寸批次、接口随模式变化的 torchvision 模型、优化器与随机数状态、指标后端和视觉证据。短脚本可以隐藏这些依赖，但这样即使两次运行使用同一个 YAML，也不一定代表同一个实验。

本仓库是围绕 Pascal VOC 2007 的学习项目，需要离线随机权重路径、受控模型对比、安全续训、只依赖检查点的预测，以及可以审计范围的产物。项目还必须区分合成或 VOC 形状夹具与官方协议。作出本决策时还没有完整 VOC 运行，`configs/reference_fasterrcnn.yaml` 只是一套步骤。后来完成的[实测运行](../recorded-run/README.zh-CN.md)满足证据门槛，不改变本架构决策。

项目维护三个 torchvision 模型和一个 VOC 提供器。目前还没有足够稳定的提供器与模型多样性、迁移机制或安全策略，无法承诺加载任意外部代码。

## 决策

采用六项明确契约。

### 1. 固定且根据内容生成的清单

准备阶段在训练前校验全部源样本和划分成员，再发布固定的 `train.csv`、`valid.csv`、`test.csv`、`dataset.yaml`、`source.yaml` 与 `summary.txt`。划分哈希覆盖每一行、相对路径和完整 JPEG/XML 字节；组合标识覆盖数据集名称、有序前景类别、坐标约定和划分哈希。

清单只引用源路径，不复制源数据。官方准备要求 train/valid/test 数量为 2501/2510/4952。`--allow-nonstandard-counts` 只跳过这些数量要求，保留全部结构和内容检查，从而避免把非标准夹具描述成官方结果。

运行产物和检查点记录清单标识与划分哈希。续训和数据集评估要求标识相同。预测不需要清单，因为它不声明带标签数据集指标。

### 2. 自包含且有结构版本的检查点

结构版本 1 保存解析配置、稳定模型名与参数、训练权重策略、有序类别名、准确预处理契约、清单标识与划分哈希、模型/优化器/调度器状态、完成轮次、最佳指标、历史、环境元数据，以及 Python、NumPy、torch 和数据加载器随机数状态。

消费者通过 `torch.load(..., weights_only=True)` 加载，并要求准确结构与预处理。评估和预测用 `weights="none"` 重建注册架构，再加载保存状态，因此不会重新下载训练骨干网络权重。预测不需要 YAML。续训只允许改变总轮次、工作进程数、设备、输出根目录和运行名；语义变化必须开始新运行。

### 3. 保留 torchvision 的模式契约

数据集返回浮点 RGB 张量列表和对齐的目标映射。Torchvision 负责检测器归一化、缩放、填充、骨干网络/FPN/RPN/ROI 或单阶段内部结构，以及后处理。

训练模式接收图像和目标，返回具名标量损失。评估模式接收图像，返回检测框、标签和分数。训练器校验并求和返回的损失映射，不使用项目专用输出对象隐藏它；评估直接消费预测映射。

### 4. 发现、检查与比较默认不修改输入

`show-config`、`list-models` 和 `model-info` 不构造模型、不检查或下载权重，也不写运行产物。`inspect-data` 有界读取准备后的划分，不修改它。`compare-runs` 读取现有运行产物且不会编辑它们；可选 `--output` 只创建单独的新 CSV，并拒绝覆盖。

这些命令在昂贵或修改状态的工作前公开选定值、来源、注册元数据、清单标识和配置差异。它们报告证据，不宣称某个模型普遍最好。

### 5. 原子发布产物

清单准备、评估和目录预测会在目标旁边暂存完整目录，通过 `os.replace` 发布；替换失败时恢复备份。检查点和训练 YAML/CSV 使用临时文件再替换，预测与评估 JSON 也原子写入。单图预测 PNG 会在防覆盖检查后直接保存，这是已知的较窄完整性边界。目录评估和目录预测默认拒绝非空目标，除非明确使用 `--overwrite`。单图预测只检查所选图像文件名对应的 JSON/PNG 是否冲突，因此输出目录可以包含无关文件。新运行目录永不复用。

对于暂存目录发布和单独原子写入的 JSON/CSV/检查点文件，未完成工作不能出现在对应最终名称下。直接保存的单图 PNG 是明确例外。完整写出的产物仍可能描述有界或质量不佳的实验，因此原子性是完整性属性，不是性能结论。

### 6. 在设计外部接口前保持内部扩展

模型构造器和 `ModelSpec` 位于内部注册表。数据集支持固定为 `voc2007`；真正不同的提供器需要修改仓库。配置不能导入任意 `module:function` 工厂，不自动发现入口点，检查点也不序列化用户可执行代码。

新的内部模型必须保持离线 `weights="none"`、固定具名骨干网络策略、模式行为、检查点重建、测试和双语文档。新的内部数据集必须保持准备与运行时分离、目标张量、划分与标识规则、预检查和证据语义。这不是稳定的外部插件接口。

## 考虑过的替代方案

### 每次运行扫描原始数据并重新划分

这样能减少清单代码，但文件系统顺序、随机划分、延迟校验和源内容修改都可能改变实验含义，也难以证明检查点与数据兼容。拒绝该方案，采用固定准备成员和内容标识。

### 只哈希路径、时间戳或划分标识

这样比读取全部字节快，但标注或图像改变时标识可能不可靠，时间戳也可能在内容不变时改变。对 VOC 规模的学习运行而言，内容可信度比准备速度更重要，因此拒绝。

### 只保存模型权重并要求原始 YAML 与代码

这样检查点更小更简单，但类别顺序、预处理、架构参数、清单标识和续训状态会成为外部隐藏依赖，因此项目检查点不采用。结果是文件更大，而且结构迁移必须显式处理。

### 使用不受限制的 pickle 保存任意对象

这样可以用较少结构代码保存自定义调度器和工厂，但加载时可能执行代码，可移植性也不透明，因此拒绝。安全张量与容器加载限制了可进入检查点的内容，字段必须明确。

### 把训练与评估包装成统一检测器输出

包装可以隐藏 torchvision 的模式变化，但会掩盖学习者需要理解的接口，并增加损失与预测适配风险，因此拒绝。项目直接讲解两种模式，并在训练器与评估器边界检查输出。

### 让检查命令构造模型或下载缺失资源

这样可以获得更丰富元数据，但列出模型可能意外消耗网络、缓存、内存或时间，因此拒绝。元数据显式注册；构造属于试运行或训练。

### 直接增量写最终目录和文件

这样更简单，也可暴露进度，但中断的准备或评估可能看起来已经完成，并覆盖以前证据，因此最终产物不采用。日志与进度可以是临时信息，契约文件只在成功替换后出现。

### 现在就支持外部工厂或自动插件

这样能更快支持任意模型与类别，但导入信任、依赖报告、配置校验、目标与类别结构、检查点可移植性、版本和错误信息都尚未解决，因此版本 0.1 拒绝。只有先制定有版本的接口及安全与兼容决策，才重新考虑。

## 结果

准备会读取每个引用图像和 XML 以校验并哈希，因此产生 I/O 成本，源内容改变后必须重做。运行时仍依赖记录的相对目录下的源数据；清单不是可移植副本。

检查点包含优化器、历史和随机状态，因此更大。它仍依赖注册架构代码和结构版本；删除或改变注册项需要迁移，或明确接受兼容性中断。安全加载改善信任边界，但不能证明张量值无害，也不能证明检查点在科学上有效。

torchvision 契约使实现保持精简，示例也更易迁移，但行为可能依赖固定的 torch/torchvision 版本和模型自有后处理，因此必须记录后端版本与解析环境。

原子暂存需要额外临时磁盘空间和同一上级目录内的替换。显式覆盖和唯一运行名要求更谨慎管理产物，但能减少证据意外丢失。若单图 PNG 渲染时进程崩溃，最终路径仍可能留下不完整 PNG；目录预测通过暂存避免该缺口。

封闭扩展面暂时限制了任意类别自定义数据集和外部模型。贡献者必须修改核心代码和测试。在项目能够支持稳定、安全、可移植的插件契约前，这是有意选择。

这些决策使来源和失败边界可以检查，但不能保证不同硬件、工作进程调度、框架版本或非确定性内核之间得到逐位相同结果，也不能把试运行、有界样本实验或配方变成完整 VOC 结果。
