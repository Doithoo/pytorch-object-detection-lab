# Pascal VOC 2007 Protocol

[Simplified Chinese](voc2007.zh-CN.md) | [Dataset contract](dataset-format.md)

This page is for users who need to distinguish the official Pascal VOC 2007 protocol from a compatible fixture. It records source identities and split rules implemented by this repository; it does not publish a detector result.

## Official archives

| Archive | URL basename | Published MD5 |
|---|---|---|
| train/validation | `VOCtrainval_06-Nov-2007.tar` | `c52e279531787c972589f7e41ab4ae64` |
| test | `VOCtest_06-Nov-2007.tar` | `b6e924de25625d8de591ea690078ad9f` |

```bash
uv run python scripts/download_data.py --data-dir data/raw
```

The downloader stores archives under `data/raw/archives`, reuses an existing archive only if its MD5 matches, downloads to `.part`, verifies before replacement, and removes the partial file on failure. Extraction rejects absolute paths, traversal, links, and non-file/non-directory members. Conflicting existing extracted files fail instead of being overwritten.

## Official split contract

| Runtime split | VOC file | Required images |
|---|---|---:|
| `train` | `ImageSets/Main/train.txt` | 2501 |
| `valid` | `ImageSets/Main/val.txt` | 2510 |
| `test` | `ImageSets/Main/test.txt` | 4952 |

```bash
uv run detect prepare-data --data-dir data/raw --manifest-dir data/manifests
```

Preparation requires exact counts, unique IDs within each split, and no ID overlap between any pair. It then validates every referenced JPEG/XML pair and atomically publishes content-derived manifests. Successful stdout prints one identity and all three counts.

`--allow-nonstandard-counts` removes only the three count requirements. It does not relax split disjointness, file pairing, XML schema, supported classes, coordinate validity, image decoding, filename matching, or dimension matching. Use it for deterministic tests and intentional VOC-shaped data, never to hide an incomplete official download.

## Difficult and test discipline

VOC `difficult=1` targets are excluded from training and ordinary target counts but retained as `iscrowd=1` for evaluation and evidence. AP/AR use the torchmetrics `MeanAveragePrecision` COCO-style backend, so this project does not claim bit-for-bit identity with the historical VOC evaluation program. Backend versions and thresholds are recorded in evaluation artifacts.

Use train for optimization and valid for checkpoint/hyperparameter selection. Evaluate test only after choices are fixed. A run with sample limits, changed splits, nonstandard counts, or changed classes is not a complete official-protocol result.

The [recorded reference run](../recorded-run/README.md) satisfies this evidence boundary and reports test `map_50_95 = 0.322312` for one validation-selected checkpoint. It includes manifest identity, split hashes, resolved config, checkpoint hash, backend versions, runtime, and final artifacts. A recipe or another unrecorded execution is still not equivalent evidence.
