A beginner-oriented, reproducible PyTorch and torchvision lab for learning a
complete Pascal VOC 2007 object-detection workflow. It exposes the data,
configuration, model, optimization, evaluation, checkpoint, and inference
boundaries instead of hiding them in one training script.

This is for learners who know basic Python, tensors, loss, and gradients but
have not yet completed an object-detection project. The guided route teaches
VOC boxes and difficult targets, variable-size detection batches, Faster R-CNN
train/eval contracts, named losses, fixed manifest identity, validation-based
model selection, and checkpoint-only prediction.

> **Recorded result:** One 26-epoch run of the reference Faster R-CNN recipe
> completed on the official VOC 2007 splits. The reserved 4,952-image test
> split produced `map_50_95 = 0.322312` and `map_50 = 0.609917`; training took
> 3,025.660 seconds on one Tesla T4. See the [full evidence, configuration,
> metrics, failures, and limits](docs/recorded-run/README.md). This is one
> reproducible project run, not a universal benchmark claim. The 145 MB
> checkpoint is not committed; its SHA-256 is recorded with the evaluation.

## First workflow

Complete this path once before changing models or removing sample limits:

```text
download -> prepare -> inspect -> dry run -> train -> evaluate -> predict
```

### 1. Install and discover the CLI

Install Python 3.10-3.12, [uv](https://docs.astral.sh/uv/), and the exact locked
development environment. `git clone` and `uv sync --locked --extra dev` may
access the network unless the repository and all locked dependencies are
already available locally or in cache:

```bash
git clone https://github.com/Yashowhoo/pytorch-object-detection-lab.git
cd pytorch-object-detection-lab
uv sync --locked --extra dev
uv run detect --version
uv run detect list-models
uv run detect model-info fasterrcnn_mobilenet_v3_large_320_fpn
```

The stable output to recognize is:

```text
0.1.0

name	family	weights
fasterrcnn_mobilenet_v3_large_320_fpn	two_stage	none,imagenet1k_v1
fasterrcnn_resnet50_fpn	two_stage	none,imagenet1k_v1
ssdlite320_mobilenet_v3_large	one_stage	none,imagenet1k_v1

name: fasterrcnn_mobilenet_v3_large_320_fpn
family: two_stage
description: Compact Faster R-CNN baseline with a MobileNet V3 FPN backbone.
weights: none, imagenet1k_v1
parameters:
  min_size: Shorter image edge used by the internal detector transform.
  max_size: Maximum longer image edge after resizing.
  box_score_thresh: ROI prediction score threshold applied by the model.
input_notes:
  - Accepts a list of float RGB tensors in [0, 1].
  - Training targets use zero-based continuous xyxy boxes.
```

Model discovery reads registry metadata only: it does not construct a detector,
download weights, or write artifacts.

### 2. Download and prepare official VOC 2007

After installation, this is the dataset network boundary. It downloads the
official train/valid and test archives, verifies their published MD5 checksums
before extraction, and stores them under `data/raw`. The repository does not
include the full dataset.

```bash
uv run python scripts/download_data.py --data-dir data/raw
uv run detect prepare-data --data-dir data/raw --manifest-dir data/manifests
```

The downloader reuses only checksum-valid archives and rejects unsafe archive
members or conflicting extracted files. After success it prints exactly:

```text
data/raw/archives/VOCtrainval_06-Nov-2007.tar
data/raw/archives/VOCtest_06-Nov-2007.tar
```

Preparation validates the official split counts and every referenced JPEG/XML
pair, then atomically writes
`train.csv`, `valid.csv`, `test.csv`, `dataset.yaml`, `source.yaml`, and
`summary.txt`. It prints split counts and a content-derived manifest identity.
It stages the complete result and atomically replaces an existing selected
manifest directory without an `--overwrite` flag. Preserve that directory or
choose another `--manifest-dir` when its contents must remain available.
Read the [VOC 2007 protocol](docs/reference/voc2007.md) before using
`--allow-nonstandard-counts`.

### 3. Inspect data before training

Inspect structured ranges and counts, then render the first four training rows
without training-time random transforms:

```bash
uv run detect inspect-data --manifest-dir data/manifests --data-dir data/raw --split train --limit 16
uv run python scripts/preview_dataset.py data/manifests --data-dir data/raw --split train --limit 4 --output artifacts/dataset_preview.png
```

`inspect-data` distinguishes full-split size from inspected rows and reports
ordinary/difficult objects, classes, image sizes, and box ranges. Open
`artifacts/dataset_preview.png` and verify box placement and labels. The preview
is deterministic for the same manifests and arguments; rerunning it replaces
the selected PNG.

### 4. Resolve configuration and perform one update

Inspect the fully typed configuration and its value sources before constructing
a model:

```bash
uv run detect show-config --config configs/learning_minimal.yaml --set run_name first-detector
uv run detect train --config configs/learning_minimal.yaml --set run_name first-detector --dry-run --device cpu
```

`show-config` does not load data, build a model, contact the network, or write a
run. The dry run uses one prepared-data batch and prints:

```text
image_shapes=((3, H, W), ...)
target_counts=(N, ...)
loss_total=...
loss_classifier=...
loss_box_reg=...
loss_objectness=...
loss_rpn_box_reg=...
dry-run OK
```

The numeric values and shapes depend on the batch. `loss_total` is the sum of
the named model losses. The four displayed loss keys are Faster R-CNN keys;
other model families may return different names. Every printed named loss must
be a finite scalar. `dry-run OK` appears only after those losses are validated
and the one real optimizer update completes. The command writes no run
directory, checkpoint, or other artifact and is not evidence that the detector
learned useful boxes.

### 5. Train the bounded learning configuration

```bash
uv run detect train --config configs/learning_minimal.yaml --set run_name first-detector --device cpu
```

This shipped learning recipe runs two epochs with limits of 32 train, 16 valid,
and 16 test images. It is intentionally bounded so a learner can exercise the
machinery; its metrics are not a full-VOC benchmark. Training writes
`artifacts/first-detector` and refuses to mix a fresh run into an existing run
directory, so use a new `run_name` for another experiment.

### 6. Evaluate validation evidence and predict a local image

While making choices, evaluate the validation split rather than repeatedly
consulting test:

```bash
uv run detect evaluate --checkpoint artifacts/first-detector/best.pt --split valid --output-dir artifacts/first-detector/evaluation-valid --device cpu
uv run detect predict --checkpoint artifacts/first-detector/best.pt --image docs/assets/detection-target-anatomy.png --output-dir artifacts/first-detector/prediction --device cpu
```

Evaluation writes aggregate and per-class AP/AR, serialized predictions,
categorized errors, and ranked evidence images. Prediction writes
`detection-target-anatomy.json` and `detection-target-anatomy.png`; using the
shipped synthetic diagram makes this command local and reproducible, but its
output is not quality evidence. Both commands reject colliding outputs by
default. `--overwrite` is an explicit replacement request, so inspect the
destination before using it.

## Choose a model and weight policy

The registry maintains exactly these names. The descriptions below follow its
metadata and do not imply measured speed or accuracy rankings.

| Registered name | Family | Maintained role and tradeoff |
|---|---|---|
| `fasterrcnn_mobilenet_v3_large_320_fpn` | `two_stage` | Compact Faster R-CNN baseline with a MobileNet V3 FPN backbone; the tutorial default. |
| `fasterrcnn_resnet50_fpn` | `two_stage` | Faster R-CNN comparison with a ResNet-50 FPN backbone; uses more memory and compute than the MobileNet Faster R-CNN recipe. |
| `ssdlite320_mobilenet_v3_large` | `one_stage` | Single-stage SSDLite comparison with a MobileNet V3 backbone; its built-in transform uses the detector's 320-pixel recipe. |

All three support `weights: none` and `weights: imagenet1k_v1`:

- `none` sets both detector and backbone pretrained weights to `None`. Model
  construction is offline and randomly initialized; VOC data must still be
  available locally.
- `imagenet1k_v1` still sets detector weights to `None` and requests only the
  pinned torchvision ImageNet backbone weights. The exact file must already be
  in the torch hub cache, or model construction may access the network to
  download it. This project never claims pretrained detector-head weights.

Use [model selection](docs/guides/using-models.md) and the
[model reference](docs/reference/model-zoo.md) before editing `model.params`.

## Read the evidence your run produced

A completed training directory is one reproducibility unit:

| Artifact | What it records |
|---|---|
| `config.yaml` | Fully resolved typed configuration used by the run. |
| `run.yaml` | Environment, device, seed, revision, ordered classes, manifest identity, and split hashes. |
| `metrics.csv` | Per-epoch named training losses and validation metrics. |
| `best.pt` | Self-contained checkpoint from the best validation `map_50_95` seen so far. |
| `last.pt` | Most recently completed epoch plus optimizer, scheduler, history, and resume state. |

Evaluation adds `evaluation.json`, `per_class.csv`, `predictions.json`,
`errors.csv`, and `visualizations/`. Single-image prediction keeps floating-point
boxes, scores, each detection's resolved class name, and manifest identity in
JSON while saving an annotated PNG separately. The checkpoint preserves the
full ordered class list. Read the [metrics and evaluation artifact
reference](docs/reference/metrics.md) and [checkpoint
schema](docs/reference/checkpoint-schema.md) rather than inferring provenance
from filenames.

The manifest identity binds source images, XML annotations, classes,
coordinates, and split membership. Runs with different identities are not the
same data experiment. Compare compatible validation runs with one declared
metric:

```bash
uv run detect compare-runs artifacts/experiment-a artifacts/experiment-b --metric valid_map_50_95 --output artifacts/comparison.csv
```

`compare-runs` verifies matching manifest identities and reports semantic
configuration differences. When `--output` is supplied, it refuses an existing
CSV instead of replacing it; choose a new output path. Select recipes and
checkpoints on validation, then freeze the protocol and use the reserved test
split once for the final report. A bounded or altered split remains bounded
evidence even when evaluated on `test`.
