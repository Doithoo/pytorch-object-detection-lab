# Checkpoint Schema Version 1

[Simplified Chinese](checkpoint-schema.zh-CN.md) | [Metrics schema](metrics.md)

This reference is for checkpoint consumers, resume debugging, and artifact audits. Project checkpoints are self-contained for prediction, but evaluation still requires matching prepared labeled data. Only schema version `1` is accepted.

Schema version `1` is frozen for the first `0.1` release. Earlier local development checkpoints that also used `schema_version: 1` but lack `lineage_id` or `run_metadata.cuda_device_count` are intentionally incompatible; regenerate them rather than weakening validation. No released checkpoint format is being migrated.

## Top-level mapping

| Field | Type | Responsibility |
|---|---|---|
| `schema_version` | integer `1` | Selects the exact compatibility rules. |
| `lineage_id` | nonempty string | Stable identifier generated by a fresh run and inherited by every resume descendant. |
| `config` | mapping | Complete resolved `AppConfig`, including paths, limits, model/training/evaluation settings, device, output, and run name. |
| `model` | mapping | `name` registry key or user-facing name, optional `factory` `module:function`, and constructor `params` needed to rebuild architecture. |
| `weight_policy` | string | Training provenance (`none` or `imagenet1k_v1`); restore does not redownload it. |
| `class_names` | nonempty ordered sequence | `background` first, then foreground names; restores label meaning. |
| `preprocessing` | exact mapping | Model input ownership and representation, detailed below. |
| `manifest_identity` | nonempty SHA-256 string | Binds model state to prepared data content/protocol. |
| `split_hashes` | mapping | `train`, `valid`, `test` content hashes for provenance. |
| `model_state` | state mapping | Model tensors loaded after architecture reconstruction. |
| `optimizer_state` | state mapping | Optimizer groups and tensor state for resume. |
| `scheduler_state` | mapping or `null` | Step scheduler state when configured, otherwise null. |
| `epoch` | positive integer | Most recently completed epoch in this payload. |
| `best_metric` | finite number | Maximum recorded `valid_<config.train.best_metric>` through `epoch`. |
| `metric_history` | sequence of mappings | All completed `metrics.csv` rows through `epoch`. |
| `run_metadata` | mapping | Environment and run identity snapshot. |
| `rng_state` | mapping | Python, NumPy, torch, CUDA, and DataLoader generator state for resume. |

`model` contains `name`, `factory` (null for built-in models or an explicit `module:function` path), and `params`. Checkpoint evaluation and prediction call the registered constructor or saved external factory with saved class count and `weights="none"`, then load `model_state`. No model-weight network access or input YAML is required for prediction. External factory code is imported only during model reconstruction; it is never executed by `load_checkpoint`.

## Exact preprocessing settings

```yaml
resize_owner: torchvision_model
input_range: [0.0, 1.0]
color_space: RGB
```

The mapping must match exactly. Missing keys, changed values, or additional keys fail schema v1 validation. Images are RGB float tensors in `[0,1]`; the registered torchvision model owns normalization, resizing, and internal batching.

## Run and RNG metadata

`run_metadata` contains `python`, `torch`, `torchvision`, `platform`, resolved `device`, nonnegative `cuda_device_count`, and `seed`; `git_revision` is a commit string or null when unavailable. A CUDA device is always recorded with an explicit index such as `cuda:1`; an implicit CUDA request is normalized with the current device index before saving, and bare `cuda` is invalid checkpoint metadata. Training also includes `manifest_identity`, `split_hashes`, and ordered `class_names` in this mapping, so the environment record can be read without joining other files.

`rng_state` contains Python's state tuple; NumPy `bit_generator`, integer `state` sequence, `position`, `has_gauss`, and `cached_gaussian`; torch CPU state tensor; and the training DataLoader `loader_generator` tensor. Its CUDA sequence has exactly `run_metadata.cuda_device_count` nonempty one-dimensional byte tensors. CPU and MPS runs record count `0` and an empty sequence. A CUDA checkpoint records a positive count, and the explicit source index parsed from `run_metadata.device` must be within that sequence. Historical best and resume checkpoints validate this topology independently, so a CUDA historical best can accompany a later CPU checkpoint. When the current device is CUDA and available, resume maps only the saved source-device state to the resolved current CUDA device; otherwise CUDA restoration is skipped.

## Safe and atomic loading

`save_checkpoint` writes a uniquely named temporary file in the destination directory and publishes it with `os.replace`; failed saves remove the temporary. `load_checkpoint` calls `torch.load(..., weights_only=True)` and rejects pickle globals that are outside the tensor/container allowlist. It then requires a mapping and exact schema version. Do not use `weights_only=False` for an untrusted file.

```python
from pathlib import Path
from object_detector.training.checkpoint import load_checkpoint

checkpoint = load_checkpoint(Path("artifacts/run/best.pt"))
print(checkpoint["schema_version"], checkpoint["epoch"])
```

## Resume identity and allowed changes

Resume requires exact equality for model name, ordered classes, manifest identity, preprocessing, and every resolved config field except:

| May change | Rule |
|---|---|
| `train.epochs` | must be greater than saved `epoch` |
| `data.num_workers` | operational loader setting |
| `device` | operational execution setting |
| `output_dir` | allowed by config identity; destination safety still applies |
| `run_name` | allowed by config identity; destination safety still applies |

Batch size, optimizer, scheduler, learning rate, augmentation, sample limits, seed, AMP, model parameters, weights policy, and evaluation settings may not change during resume. In-place resume must use the existing `last.pt`; `best.pt` or an older copy is rejected while `last.pt` exists. If `last.pt` is missing, only that exact run directory's `best.pt` may recover it; any other checkpoint requires a new empty run directory. A different requested run directory must be empty. Cross-directory resume from `last.pt` also requires a sibling `best.pt` with the same `lineage_id` and exact model, class, preprocessing, manifest, and split-hash semantics; cross-directory resume from `best.pt` uses that checkpoint itself. Full config and run-metadata snapshots need not match because allowed resume settings and execution environments can change. Every resumable checkpoint requires each configured validation-metric history value to be a finite non-boolean number and `best_metric` to equal the maximum across the complete history; later ties are valid. A historical `best.pt` additionally requires its final value to equal `best_metric` and strictly exceed every earlier value. After validation, that payload is atomically published as the new run's `best.pt` without rewriting its source epoch, resolved config, or run provenance. A different experiment needs a new run, not edited checkpoint fields.

Evaluation additionally loads the saved config, requires current `dataset.yaml.identity` to equal `manifest_identity`, records checkpoint SHA-256, and writes a new atomic artifact directory. Prediction needs only the checkpoint and input images. See [troubleshooting](../guides/troubleshooting.md) for specific errors and fixes.
